# Voice Provider External Services

This document records the provider configuration contracts used by the unified voice architecture. Real credentials and model services are optional; automated tests mock these services.

## Common Settings

| Key | Meaning |
| --- | --- |
| `voice_provider` | Default speech synthesis provider |
| `transcription_provider` | Default ASR provider |
| `voice_flow_defaults_json` | Per-flow provider overrides |
| `voice_fallback_order` | Comma-separated fallback provider ids |
| `voice_output_dir` | Generated voice task output directory |
| `voice_require_disclosure` | Whether generated voice metadata requires disclosure |

## Edge TTS

- Provider id: `edge_tts`.
- Requires the `edge-tts` command/package to be available.
- Used by video generation by default when configured.
- Manual smoke test: create a short `/ai-voice` task with provider `edge_tts`.

## OpenAI Speech

- Provider id: `openai_speech`.
- Required: `openai_speech_api_key`.
- Optional: `openai_speech_base_url`, `openai_speech_model`, `openai_speech_voice`, `openai_speech_response_format`.
- Contract: `POST {base_url}/v1/audio/speech` with `model`, `input`, `voice`, and `response_format`.
- Smoke test only when a valid API key is available.

## Azure Speech

- Provider id: `azure_speech`.
- Required: `azure_speech_endpoint` or region-derived endpoint, plus `azure_speech_api_key`.
- Optional: `azure_speech_voice`, `azure_speech_output_format`.
- Contract: SSML payload posted to Azure Speech synthesis endpoint.
- Smoke test only when Azure Speech credentials are available.

## MiniMax Speech

- Provider id: `minimax_speech`.
- Required: `minimax_speech_api_key`.
- Optional: `minimax_speech_base_url`, `minimax_speech_model`, `minimax_speech_voice`.
- Default model: `speech-2.8-hd`.
- Supported modes:
  - plain TTS via `/v1/t2a_v2`.
  - `voice_design` via `/v1/voice_design` then generated audio materialization.
  - `reference_clone` via upload + `/v1/voice_clone` + `/v1/t2a_v2`.
- Reference clone requires explicit safety gate and a local reference file under the configured safe directories.

## VoxCPM

- Provider ids: `voxcpm_openai_speech`, `voxcpm_http`.
- OpenAI-compatible contract: `POST /v1/audio/speech`.
- Generic HTTP contract accepts JSON and returns raw audio, `audio_base64`, `audio_hex`, same-origin `audio_url`, or safe local `audio_path`.
- Run the model/service outside this repository process. Do not add CUDA, vLLM, or VoxCPM runtime dependencies to base requirements.

## VibeVoice

- TTS provider ids: `vibevoice_tts`, `vibevoice_realtime`.
- ASR provider ids: `vibevoice_asr`, `vibevoice_vllm_asr`.
- TTS service contract mirrors the generic HTTP audio response contract.
- ASR service contract posts a media file plus `model`, `language`, and `hotwords`; responses may contain `text`, `transcript`, `content`, or OpenAI-like `choices[0].message.content`.
- `vibevoice_vllm_asr` defaults to `/v1/audio/transcriptions`.
- Run VibeVoice/vLLM as an external service. Do not install large-model dependencies into the base app.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Provider missing from select | Call `/api/voice/providers?capability=speech_synthesis&flow=manual_voice`; confirm provider id and config fields |
| Provider shown as unconfigured | Fill the required endpoint/API key in Settings; saved secret placeholders do not count as new keys |
| Smoke test fails with invalid key | Re-enter the API key; endpoint changes require re-entering the matching secret |
| Local HTTP task fails | Confirm service URL, timeout, and response format |
| Audio file will not play | Confirm output path is under `voice_output_dir` and the file exists |
| Reference clone rejected | Confirm safety gate, file extension, size, and directory |
| Article ASR did not use VibeVoice | Check `voice_flow_defaults_json` contains `article_generation.transcription` and the VibeVoice ASR URL is configured |

## Manual Verification Recipes

1. Set `tts_workflow=silent` in a video task and confirm video generation completes with a silent WAV.
2. If `edge-tts` is installed, set `voice_provider=edge_tts` and confirm video narration is generated by Edge.
3. Configure an invalid `local_tts_url`, explicitly select `local_http_tts`, and confirm the task fails visibly.
4. Run `/api/voice/smoke-test` with `openai_speech`, `azure_speech`, `minimax_speech`, `voxcpm_http`, or `vibevoice_tts` only when the corresponding real endpoint and credentials are available.
5. Configure `article_generation.transcription=vibevoice_asr` and run an article task with no usable subtitles against a real VibeVoice ASR service.
