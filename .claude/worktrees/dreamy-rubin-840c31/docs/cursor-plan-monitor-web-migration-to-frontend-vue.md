# monitor_web → frontend-vue 迁移方案（Cursor）

- **成文日期**：由生成时 `datetime.now().strftime("%Y-%m-%d")` 得到：**2026-04-23**
- **状态**：可执行技术方案（非产品需求说明）
- **范围**：在保留 `monitor_web` 原站作为对照的前提下，以 `frontend-vue` 为唯一增量代码库，逐页替代浏览器实际加载的前端；后端仍以现有 `server` HTTP API 为准。

---

## 1. 已冻结的架构决策

- **唯一工程**：`frontend-vue/` 为监控 Web 控制台 **唯一** 长期维护的前端；构建产物 `frontend-vue/dist` 与 `server/__main__.py` 中优先静态托管逻辑保持对齐。
- **真值与回退**：`monitor_web` **不删、不大改**（除非修复线上 bug），在迁移全周期内作 **布局/交互/功能对照** 与回退基线；新功能、新页 **只进 `frontend-vue`**。
- **技术栈统一**：新代码一律采用当前 `frontend-vue` 约定（Vue 3、Vite、组合式 API、既有 UI 与请求层），不复刻「纯 HTML 字符串拼接」式实现，但 **行为与信息架构** 须与 `monitor_web` 一致。

参考对比分析：`docs/analysis_results.md`。

---

## 2. 资源嗅探页：重要约束（与常规迁移不同）

| 来源 | 功能 | 样式 | 迁移策略 |
|------|------|------|----------|
| **frontend-vue** 当前资源嗅探 | ✅ 已验证通过 | 一般，需美化 | **以本实现为唯一功能源**，不在此功能上再抄 `monitor_web` 的业务逻辑。 |
| **monitor_web** 资源嗅探 | ❌ 功能错误/不可用 | 尚可 | **禁止** 把 `monitor_web` 该页当迁移模板；**不迁移** 其功能实现。 |

**执行要点**：

- 在统一壳与全局样式后，**直接沿用并迭代 `frontend-vue` 中的资源嗅探页**（路由、组件、API 调用以当前 Vue 实现为准）。
- **视觉**上可对齐 `monitor_web` 中该页「还行」的那部分：表格疏密、顶栏操作区、标签筛选等 **外观层级**，通过 **样式 / 通用人机组件** 在 Vue 内复刻，而不是复制其 HTML/JS 逻辑。
- 若全站将收敛到 `DESIGN.md`（见§5），则资源嗅探页 **同样走统一 token/卡片/表格皮肤**，在保持可用性的前提下变好看、且与全站 **风格一致**。

---

## 3. 分阶段计划

### 3.1 大框架先迁移（壳 + 路由 + 全局能力）

1. 对照 `monitor_web` 的侧栏/顶栏/主区结构，在 `frontend-vue` 中实现 **等价信息架构**（一级、二级如 settings 子项与现有一致，路由命名与现用户心智一致）。
2. 提供全局 **布局组件**（顶栏标题随路由、侧栏当前项、主内容区留白与 `max-width` 与现站可测量对齐）。
3. 接好横切能力：**i18n、Token/401 与现有一致、全局错误与 loading** 等，避免每页各写一套。

**退出条件**：不迁移具体业务大页时，**仅壳** 在常见分辨率下与 `monitor_web` 导航与布局无结构性偏差；已存在的资源嗅探页在壳下无错位、双滚动条等明显问题。

### 3.2 各业务模块逐页迁移

按 `docs/analysis_results.md` 中模块列表，**建议顺序**（可按依赖微调）：

1. **Dashboard**（与「首页一致」强相关，优先）  
2. 账户/频道、批量下载、API Keys、代理池、动态代理、切片历史、视频详情 等，**一次一模块、可独立回归**。  
3. **设置中心** 多子页，在壳稳定后整体迁入；子导航与现 `settings-*` 行为对齐。

**每模块完成定义**：同入口下，主流程、主 API、空态/错误与 `monitor_web` **行为一致**；侧栏/顶栏不漂。

### 3.3 首页与全站：布局与操作一致

- 用**可勾选清单**验收：侧栏宽、顶栏、主区 padding、表格与操作列、按钮位置、批量与筛选、模态、分页。  
- **对照**方式：`monitor_web` 与 `frontend-vue` 同构路由 **双开对比**；必要时为关键流补充自动化测试（可沿用/扩展仓库内现有 i18n 或 UI 测例思路）。

---

## 4. 不做什么（防返工）

- 不把 `monitor_web` 资源嗅探页的 **实现** 迁移过来；只吸收其**可借鉴的视觉层级**（在 Vue 内用样式与组件复刻）。
- 不在 `monitor_web` 上为迁移目的做大重构或「顺便升级技术栈」。
- 不并行维护两套「正式」业务实现（`monitor_web` 仅作对照，直至下线策略另行决定）。

---

## 5. 样式与 DESIGN.md、ui-ux-pro-max

- **主策略**：以 **与 `monitor_web` 行为与布局一致** 为首要验收；若像素级与旧站冲突或全站需统一，则在 **布局壳 + 通用组件（按钮/卡片/表格/模态）** 上收敛到 `DESIGN.md` 的 **Claude 系暖色、纸感、居中内容区/卡片** 等规则，**不改信息架构与主按钮语义**。
- **ui-ux-pro-max**：在实现与走查时用作 **a11y、对比度、焦点、触摸目标、z-index、动效时长** 等检查清单；若仓库内存在 `skills/ui-ux-pro-max/scripts/search.py`，可额外对「监控类 SaaS / dashboard」跑 `--design-system` 与 `--stack vue` 作辅决策。  
- 资源嗅探页：**功能以 Vue 为准，样式在统一设计体系下美化**，并与全站 **风格一致**（见 §2）。
